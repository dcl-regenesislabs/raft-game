# UI consistency review — 2026-09-15

## Changes

- Shared dark ocean palette, bordered panels, restrained gold accents and rounded action buttons. Primary actions use teal; secondary actions use the dark cell color.
- Backpack and storage use stable outlined selections instead of shaking all other items. Both panes in storage now have equal cell sizes; all 30 backpack slots remain accessible.
- Tool dropdown, crafting recipes, cooking supplies and recipe book use explicit mobile pages. On the Motorola, dragging a scroll list moved the camera and could select a row. Paging removes that dependency; desktop retains scrolling.
- Paging reserves room for 48px navigation buttons and clamps the current page when inventory contents shrink. Tool row labels flex to leave room for the selected checkmark.
- Recipe rows no longer shrink to fit long lists. Cooking and crafting use consistent panel heights, padding, dividers and readable text.
- Settings and ending screens fit their contents inside the safe area. The settings header and close control remain outside its scrolling body. Death/victory share one presentation with fade-gated buttons.
- Native jump, joystick and crosshair hide during endings and restore on return to play. Desktop cursor release and action locks now include victory.
- Menu transitions and guide dismissal/reopening use the mobile input gate. Corrected the guide's hammer/cup confusion, cup-fill instruction and desktop tool-selection instructions.

## Device verification

Motorola Edge 60 Pro, ADB `0089321234`, Explorer 1.14.0.1925 staging, landscape 2712×1220, local preview, DEBUG_MODE enabled.

Checked on-device:

- Main HUD, vitals, tool dropdown and hammer selection; all five seeded entries are legible; hammer selection closes the dropdown.
- Backpack open/close and moving the hammer between inventory slots.
- Crafting rope, selecting recipes, paging to the final page containing storage/anchor, and reaching the close button.
- Cooking supplies page 1 → 2, selecting Grilled Sardines, populated ingredient/fuel/output previews, enabled Cook action, and starting the grill (food and fire visible after the panel closes).
- Storage transfer: moving plastic from storage to an empty player slot moved 20 items and reduced storage from 99 to 79. Final equal-cell layout checked after rebuild.
- Settings layout, guide reopen, and a long press/release on Hide Guide without starting hook charge.
- Death presentation and Play Again; victory presentation and Keep Playing. Found and fixed leftover native movement/crosshair controls on these screens; checked the corrected visibility on the phone.

A temporary local-only command driver opened cooking/storage/end states directly for inspection. It was removed from source and the final bundle. Endings were inspected as debug states, not earned through a complete survival run. Existing Explorer-owned profile/debug/emote chrome is outside scene UI control.

## Automated checks and limits

- SDK build and TypeScript check.
- 20 mobile-control regression tests, including native controls hiding/restoring around endings.
- 7 UI tests: fade input suppression, narrow-safe-area bounds, reaching all 30 equipped inventory entries plus Hands, page clamping/space, tutorial wording/touch targets and desktop scrolling.
- Gameplay regression suite: 24 pass, 2 existing failures. Bonus hunger is clamped away by survival drain; purifier output can exceed fuel available during a long frame. These are gameplay issues previously recorded in gameplay-qa-2026-09-15.md, not resolved in this UI pass.
- Desktop behavior was reviewed in source/tests; no fresh desktop Explorer visual pass. Phone visual verification covers the connected Motorola in landscape, not every device/orientation.
- Save/load/auth synchronization remains excluded. Their menu controls retain the existing service behavior.
